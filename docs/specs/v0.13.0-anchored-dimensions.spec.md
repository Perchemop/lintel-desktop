# v0.13.0 Anchored Dimensions — Feature Specification

**Status:** Draft (feature-forge interview complete)

**Priority:** Must-have (blocking)

## 1. Overview & User Value

### Problem Statement
Current dimensions in Lintel are free-floating point pairs: they measure between two absolute coordinates and do not track the wall geometry they measure. When a wall moves, the dimension stays at its original coordinates, requiring manual re-positioning. This breaks the professional drafting workflow where dimensions must remain accurate through design iterations.

### Target Users
- **Architects** producing construction documents — need dimensions that stay correct through design iterations
- **Draftspeople** producing permit sets — require reliable, auditable measurements
- **Home designers / DIY** — occasional users who need dimensions to "just work"

### User Value
- **Eliminates manual rework** — dimensions auto-update when walls move
- **Guarantees accuracy** — measurements always reflect current geometry
- **Professional parity** — matches standard CAD anchored-dimension behaviour
- **Reduces errors** — no forgotten dimension updates after edits

### Success Criteria (Definition of Done)
1. **Core behaviour**: Wall move → anchored dimension auto-updates (headless test)
2. **Persistence**: Save/load round-trip preserves anchors and constraints
3. **UI**: Click-to-place witness lines on canvas (hover preview, click + inspector, drag from endpoint)
4. **Performance**: Constraint solver < 50ms for 500 constraints

## 2. Functional Requirements (EARS Format)

### 2.1 Dimension Anchors

**REQ-ANCH-001**  
The system shall provide a `DimensionAnchor` type that references a wall by `WallId` and a parametric position `param ∈ [0, 1]` along that wall's centreline.

**REQ-ANCH-002**  
When a `DimensionAnchor` has `perpendicular = true`, the system shall resolve it to the point on the wall at `param` with a perpendicular witness line.

**REQ-ANCH-003**  
Where a `Dimension` has `start_anchor = Some(anchor)`, the system shall derive the dimension's start point from `anchor.resolve_on(wall)` rather than the stored `start` coordinate.

**REQ-ANCH-004**  
Where a `Dimension` has `end_anchor = Some(anchor)`, the system shall derive the dimension's end point from `anchor.resolve_on(wall)` rather than the stored `end` coordinate.

**REQ-ANCH-005**  
The system shall support `DimensionAnchor::Free` (no wall reference) for backward compatibility; a `Free` anchor resolves to the stored coordinate.

### 2.2 Constraint System

**REQ-CONST-001**  
The system shall provide a `Constraint` enum with variants:
- `PerpendicularDistance { wall_id, param, dimension }` — dimension measures perpendicular to wall at `param`
- `FixedAngle { dimension, degrees }` — dimension angle is fixed relative to horizontal
- `EqualLength { a, b }` — two dimensions have equal measured length

**REQ-CONST-002**  
When a `Constraint::PerpendicularDistance` is added to a level, the system shall validate that `wall_id` exists, `param ∈ [0, 1]`, and `dimension` references an existing dimension on that level.

**REQ-CONST-003**  
The system shall reject adding a constraint that would create a circular reference (e.g., A→B→A via `FixedAngle` or `EqualLength`).

**REQ-CONST-004**  
The system shall enforce a maximum of 500 constraints per level; attempts to exceed shall return `CoreError::LimitExceeded`.

**REQ-CONST-005**  
When a wall is deleted, the system shall cascade-delete all constraints referencing that `wall_id` and remove corresponding anchors from affected dimensions.

### 2.3 Constraint Solving

**REQ-SOLVE-001**  
The system shall provide `solve_constraints(level, constraints) → Vec<ResolvedConstraint>` that computes the current geometric point for each constraint.

**REQ-SOLVE-002**  
The system shall provide `apply_constraints_to_anchors(level, constraints) → usize` that mutates anchored dimension endpoints to match resolved constraint points, returning the count of dimensions moved.

**REQ-SOLVE-003**  
Where a dimension has an anchor flagged `perpendicular`, `apply_constraints_to_anchors` shall update that anchor's `param` to match the resolved constraint point.

**REQ-SOLVE-004**  
When a `Command::MoveWall` executes, the system shall automatically run `apply_constraints_to_anchors` for all constraints on that level after the wall geometry updates.

**REQ-SOLVE-005**  
When a `Command::DeleteWall` executes, the system shall cascade-delete constraints referencing the deleted wall before removing the wall.

**REQ-SOLVE-006**  
Constraint solving shall complete in < 50ms for 500 constraints on a typical plan.

### 2.4 Persistence (Backward Compatible)

**REQ-PERSIST-001**  
Constraints shall serialize to JSON with all fields (wall_id, param, dimension, etc.) and deserialize round-trip without loss.

**REQ-PERSIST-002**  
`ResolvedConstraint` shall serialize with its `constraint` and computed `point`.

**REQ-PERSIST-003**  
When loading a project from JSON that lacks `start_anchor`/`end_anchor` fields (pre-v0.13.0 files), the system shall set both anchors to `None` (equivalent to `DimensionAnchor::Free`), preserving the stored `start`/`end` coordinates.

**REQ-PERSIST-004**  
When loading a project with constraints but no `DimensionAnchor` on the referenced dimensions, the solver shall still resolve constraints against the current wall geometry on next solve.

### 2.5 Commands

**REQ-CMD-001**  
`SetDimensionStartAnchor { id, anchor }` shall set the dimension's `start_anchor`; `anchor = None` clears it (reverts to free).

**REQ-CMD-002**  
`SetDimensionEndAnchor { id, anchor }` shall set the dimension's `end_anchor`; `anchor = None` clears it.

**REQ-CMD-003**  
`SetDimensionWitnessGap { id, gap }` shall set the witness line gap (mm) with validation `gap ≥ 0`.

**REQ-CMD-004**  
`SetDimensionWitnessOverrun { id, overrun }` shall set the witness line overrun (mm) with validation `overrun ≥ 0`.

**REQ-CMD-005**  
`AddConstraint { constraint }` shall validate and append the constraint to the level's constraint list.

**REQ-CMD-006**  
`RemoveConstraint { index }` shall remove the constraint at the given index from the level's constraint list.

**REQ-CMD-007**  
All anchor/constraint commands shall support undo/redo via the existing `Document` history.

### 2.6 Click-to-Place UI (Canvas)

**REQ-UI-001**  
When the user hovers a wall while the Dimension tool is active and an endpoint is being placed, the system shall display a preview anchor point at the cursor's parametric position along the wall.

**REQ-UI-002**  
When the user clicks a wall while placing a dimension endpoint, the system shall create a `DimensionAnchor` at the clicked parametric position, flag it `perpendicular = true`, and open the Inspector to the dimension's properties.

**REQ-UI-003**  
When the user drags from an existing dimension's endpoint grip and releases over a wall, the system shall set that endpoint's anchor to the release parametric position on that wall.

**REQ-UI-004**  
The Inspector shall display editable fields for `witness_gap` and `witness_overrun` (mm, default 2.0 and 2.0) with live preview on the canvas.

**REQ-UI-005**  
The Inspector shall display the dimension's `start_anchor` and `end_anchor` status (Free / Anchored to Wall #N at param X.XX) with a "Clear" button to revert to Free.

**REQ-UI-006**  
The Command Palette shall expose "Add Perpendicular Constraint" and "Remove Constraint" actions for the active level.

## 4. Acceptance Criteria (Given/When/Then)

### 4.1 Core Constraint Behaviour

**AC-001**  
Given a level with a wall (id=W1) from (0,0) to (3000,0)  
And a dimension D1 with `start_anchor = Some(DimensionAnchor::anchored(W1, 0.2, perpendicular=true))` and `end = (3000, 1000)`  
When the wall is moved to (1000,0)–(4000,0) via `MoveWall`  
Then D1's start point resolves to (1600, 0) [0.2 along new wall]  
And D1's end point remains (3000, 1000) [unanchored]

**AC-002**  
Given a level with wall W1 and dimension D1 anchored at start to W1 param 0.5  
And a `PerpendicularDistance { wall_id: W1, param: 0.75, dimension: D1 }` constraint  
When `apply_constraints_to_anchors` runs  
Then D1's start anchor param becomes 0.75  
And D1's start point moves to the point at 0.75 on W1

**AC-003**  
Given a project with 500 `PerpendicularDistance` constraints  
When `solve_constraints` is called  
Then it returns 500 `ResolvedConstraint` entries within 50ms

### 4.2 Persistence

**AC-004**  
Given a project with anchored dimensions and constraints saved to JSON  
When the JSON is loaded  
Then all anchors, witness_gap, witness_overrun, and constraints are restored identically

**AC-005**  
Given a v0.12.x project file (no anchor fields) with a dimension from (0,0) to (3000,0)  
When loaded in v0.13.0  
Then the dimension has `start_anchor = None`, `end_anchor = None`  
And its start/end coordinates are unchanged

### 4.3 Wall Deletion Cascade

**AC-006**  
Given a level with wall W1, dimension D1 anchored to W1, and constraint C1 referencing W1  
When `DeleteWall { id: W1 }` executes  
Then W1 is removed  
And D1's anchor is cleared (reverts to Free)  
And C1 is removed from the level's constraints

### 4.4 Click-to-Place UI

**AC-007**  
Given the Dimension tool is active and the user is placing the start point  
When the user hovers wall W1  
Then a preview anchor point is shown at the cursor's parametric position on W1

**AC-008**  
Given the Dimension tool is active and the user is placing the start point  
When the user clicks wall W1 at parametric position 0.35  
Then the new dimension has `start_anchor = Some(DimensionAnchor::anchored(W1, 0.35, perpendicular=true))`  
And the Inspector opens showing the dimension's properties

**AC-009**  
Given an existing dimension D1 with a free start endpoint  
When the user drags the start grip and releases over wall W2 at param 0.6  
Then D1's `start_anchor` becomes `Some(DimensionAnchor::anchored(W2, 0.6, perpendicular=true))`

### 4.5 Validation & Error Handling

**AC-010**  
Given a level with 500 constraints  
When `AddConstraint` attempts to add a 501st  
Then it returns `CoreError::LimitExceeded`

**AC-011**  
Given a constraint referencing wall W1  
When W1 is deleted  
Then the constraint is cascade-deleted (no error, no orphan)

**AC-012**  
Given a dimension with both ends anchored  
When `apply_constraints_to_anchors` would move both ends to the same point (zero length)  
Then the solver clamps to minimum 1mm separation and logs a warning

**AC-013**  
Given a `FixedAngle` constraint creating a circular reference A→B→A  
When `AddConstraint` validates it  
Then it returns `CoreError::CircularConstraint`

## 5. Error Handling Table

| Error Code | Trigger | User-Facing Message | Recovery |
|------------|---------|---------------------|----------|
| `LimitExceeded` | >500 constraints/level | "Maximum constraint limit (500) reached for this level" | Remove unused constraints |
| `CircularConstraint` | FixedAngle/EqualLength cycle | "Constraint would create a circular reference" | Adjust constraint selection |
| `WallNotFound` | Constraint references deleted wall | (Handled by cascade delete — never user-visible) | N/A |
| `InvalidParam` | Anchor param < 0 or > 1 | "Anchor position must be between 0% and 100% along the wall" | Re-place anchor |
| `ZeroLengthDimension` | Solver would collapse dimension | "Dimension would have zero length; minimum 1mm enforced" | Adjust geometry |
