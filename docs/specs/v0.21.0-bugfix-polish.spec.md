# v0.21.0 — Bugfix & Polish Patch Cycle

**Status:** Specification complete — ready for ticket breakdown
**Branch:** v0.21.0
**Base commit:** main (v0.20.1)

## Overview

A patch-level release focused on stability, polish, and fixing known issues from v0.20.x. No new capabilities — only fixes, improvements, and quality-of-life enhancements to existing features.

**User value:** Users get a more reliable drafting experience with fewer edge-case crashes, smoother UI interactions, and polished existing workflows.

## Functional Requirements (EARS)

### REQ-FIX-001: Flaky kittest evidence generation
**When** the `kittest` CI job runs `LINTEL_GENERATE_EVIDENCE=1 cargo test -p lintel --bin lintel evidence_`, **the** test suite **shall** complete without SIGSEGV (exit code 101).

### REQ-FIX-002: Door/window placement regression tests
**When** a door or window is placed near a wall endpoint, **the** placement **shall** project correctly onto the wall centreline without panic or misplacement.

### REQ-FIX-003: Constraint solver 2-node cycle handling
**When** two EqualLength constraints form a 2-node cycle (A ↔ B), **the** solver **shall** detect and allow the cycle without false-positive circular reference error.

### REQ-FIX-004: Anchor + constraint round-trip
**When** a project with anchored dimensions and constraints is saved and loaded, **the** anchors and constraints **shall** deserialize identically and the solver **shall** re-apply on load.

### REQ-FIX-005: Dark/high-contrast palette completeness
**Where** the theme system is active, **the** dark and high-contrast palettes **shall** meet WCAG AA (4.5:1 body text, 3:1 UI boundaries) for all semantic roles used in the app.

### REQ-FIX-006: Constraint solver performance at scale
**When** a level has 500 constraints, **the** solver **shall** complete in under 50ms on CI hardware.

### REQ-FIX-007: Inspector empty states
**When** an inspector section has no data (e.g., no constraints, no viewports, no block instances), **the** section **shall** display a helpful empty state with primary action.

### REQ-FIX-008: Inspector keyboard navigation
**When** the inspector is focused, **the** Tab order **shall** traverse all interactive controls in reading order without trapping.

## Acceptance Criteria

### AC-001: kittest reliability
**Given** a clean CI runner on Linux/macOS/Windows,
**When** the `kittest` job runs the evidence generation tests,
**Then** all 8 evidence tests pass without SIGSEGV,
**And** the job completes with exit code 0.

### AC-002: Door/window placement
**Given** a wall with an endpoint at (0,0),
**When** the user clicks near that endpoint to place a door,
**Then** the door snaps to the wall centreline,
**And** no panic occurs,
**And** the door is placed at the projected position.

### AC-003: 2-node EqualLength cycle
**Given** dimension A and dimension B,
**When** EqualLength(A, B) and EqualLength(B, A) constraints exist,
**Then** the solver treats this as a valid 2-node cycle,
**And** no circular reference error is raised.

### AC-004: Anchor + constraint round-trip
**Given** a project with anchored dimensions and PerpendicularDistance constraints,
**When** the project is saved to JSON and loaded back,
**Then** all anchors deserialize with correct wall_id, param, perpendicular,
**And** constraints deserialize with correct dimension, wall_id, param,
**And** the solver re-applies constraints on load.

### AC-005: Dark/high-contrast WCAG AA
**Given** the theme contrast test runs,
**When** it checks dark and high-contrast palettes,
**Then** all semantic role pairings meet 4.5:1 (body) / 3:1 (UI boundaries).

### AC-006: Constraint solver performance
**Given** a level with 500 PerpendicularDistance constraints,
**When** `solve_constraints` is called,
**Then** it returns in < 50ms on CI hardware.

### AC-007: Inspector empty states
**Given** the inspector "Constraints" section with zero constraints,
**When** the section renders,
**Then** it shows "No constraints — add one to pin a dimension to a wall" with an "Add" button.

### AC-008: Inspector keyboard navigation
**Given** the inspector panel is focused,
**When** the user presses Tab repeatedly,
**Then** focus moves through all controls in reading order,
**And** no focus trap occurs,
**And** focus returns to the first control after the last.

## Error Handling

| Error Condition | Response |
|-----------------|----------|
| SIGSEGV in kittest | Investigate wgpu/AccessKit interaction; add retry or skip on CI |
| Door/window projection fails | Surface clear error in status bar; leave placement unchanged |
| Constraint solver timeout | Return partial result; log warning; don't block UI |
| Dark palette contrast failure | Fail CI; block merge until palette fixed |
| Project load with invalid constraints | Migrate gracefully; log warning; keep valid constraints |
